# 维护版使用说明

## 下载位置与目录刷新

在“设置 → 常规设置 → 下载文件夹”点“选择文件夹”，或者输入路径。留空时使用启动器所在目录；目录不存在时会在开始下载时创建。模型下载完成后，该目录会自动加入模型搜索路径。

模型列表直接查询 SakuraLLM 的 HuggingFace 模型仓库，后端列表查询 llama.cpp 官方 Release。可以手动刷新，联网失败时保留缓存或内置列表；刷新列表本身不会下载文件或更新已安装的后端。动态模型缺少可信的显存评估数据时，需要手动设置上下文、并行数等参数。

下载到临时文件，成功后检查完整性及文件类型；模型提供 SHA-256 时再校验摘要。校验成功后才替换同名文件。遇到连接失败、传输中断或网站返回 HTML 错误页面，会显示原因并清理本次暂存文件。下载进度页可以取消任务，列表中的历史失败记录不会自动重试。

llama.cpp 压缩包也下载到上述文件夹，但解压安装位置仍是启动器目录下的 `llama`。安装可能替换旧后端，请先停止后端服务；CUDA 后端需要同时完成对应运行库的下载和解压。只读安装目录不适合直接安装后端或保存启动器配置：请把启动器放到可写目录，再选择模型下载位置。

## 命令模板与额外参数

在启动页展开“高级选项”，可以填写命令模板：

```text
%cmd% -t 8
```

`%cmd%` 展开为启动器生成的可执行文件、模型及界面参数，上例额外指定 8 个 CPU 线程。修改界面里已有的参数时，优先修改对应控件，避免同一参数出现两次。

```text
%cmd_raw% -c 4096 -ngl 99 --host 127.0.0.1 --port 8080 -np 1 -t 8
```

`%cmd_raw%` 只保留可执行文件与模型，其他参数都由这段模板提供。参数名和取值请以当前安装的 `llama-server --help` 为准。

模型路径请用模型选择框选择，包括含空格的模型路径；`%cmd%` 和 `%cmd_raw%` 会把选中的路径作为一个参数传递。当前自定义模板按空格拆分，不适合额外手写含空格的路径参数，也不提供 shell 管道或重定向语法。

## 预设管理

到“设置 → 配置编辑器”编辑或删除预设。点删除后会出现确认框，确认前可以取消。预设的启动参数保存后，在启动页重新选择该预设即可回读；Windows 下会跳过保留名称的预设文件。

## GGUF 模型与翻译用途

可手动准备其他 GGUF 模型，再在启动页选择。能否加载由所选 llama.cpp 后端决定；启动器不负责把通用聊天或推理模型转换成 Sakura/GalTransl 翻译模型。翻译客户端仍需使用模型要求的提示词模板。

## 启动闪退、GPU 没有工作或速度慢

1. 在“设置 → 日志”查看模型路径、后端路径、版本和生成的命令。如果后端在独立终端窗口报错，也需要保留该窗口内容；启动器日志不会自动收集独立终端的全部输出。
2. 核对后端与显卡平台是否匹配。CUDA 包及运行库须使用对应版本，不能仅下载 CPU 包后期待 GPU 加速。检查后端启动日志实际列出的计算设备和 GPU 卸载层数。
3. 新版 Flash Attention、内存映射参数由启动器查询当前后端帮助后生成。检测失败会写入日志并跳过可选参数，不代表特定 GPU 内核已经支持该功能。
4. AMD/ROCm 的 `invalid device function`、缺失 `amdhip64.dll`、多 GPU 编号问题，需要提供显卡型号、驱动、后端版本和后端设备枚举；WMI 的适配器顺序不能证明 HIP 设备编号。
5. 若仍需反馈，请附操作系统、显卡、模型文件名、后端版本、生成的启动命令、启动器日志和后端错误。不要只提交“闪退”或“很慢”。分享日志前请检查其中的本地路径、令牌和分享地址。

## 便携版与系统限制

配置、日志和目录缓存以启动器所在位置为准，不依赖快捷方式的“起始位置”。单文件程序运行时仍会由打包运行时解压临时内容；本次没有修改其临时目录或承诺异常退出后的清理行为。

Windows 和 macOS 由 GitHub Actions 执行自动化测试与构建。macOS 实机启动、特定 AMD/多 GPU 硬件和历史 `OPENSSL_Applink` 故障仍需相应环境验证。在线工作区的 `Failed to fetch` 还需要浏览器请求证据才能区分 HTTPS、CORS、连接和远端站点问题。
